# 01 项目地图

## 1. 这个例子的定位

Synacor Challenge 使用一颗很小的虚拟 CPU。GNU binutils-gdb 把它实现成示例模拟器，是因为它虽小，却同时包含一个真实 CPU 模拟器所需的基本要素：

- 寄存器；
- 程序计数器；
- 内存；
- 栈；
- 算术和位运算；
- 条件分支、调用和返回；
- 终端输入输出；
- 非法指令、正常退出；
- 指令、寄存器、内存与分支跟踪。

它不是完整硬件平台：没有 MMU、中断控制器、外设总线、操作系统 ABI 或系统调用。正因为如此，它适合成为 GNU sim 的第一课。

## 3. 三层状态对象

### 3.1 `SIM_DESC`

`SIM_DESC sd` 表示整个模拟器实例，拥有：

- CPU 列表；
- 内存和设备；
- 配置、命令行和程序信息；
- callback；
- trace/profile 状态；
- event engine；
- 当前停止原因。

通过 `STATE_CPU(sd, 0)` 可以取得第 0 颗 CPU。

### 3.2 `SIM_CPU`

`SIM_CPU *cpu` 是公共框架认识的 CPU 对象。它包含指向所属模拟器的指针、PC 访问回调、架构私有数据指针等。

常见方向：

```c
SIM_DESC sd = CPU_STATE (cpu);  /* CPU -> 整个模拟器 */
SIM_CPU *cpu = STATE_CPU (sd, 0); /* 模拟器 -> 第 0 颗 CPU */
```

### 3.3 `struct example_sim_cpu`

这是本架构真正关心的状态：

```c
struct example_sim_cpu {
  uint16_t regs[8];
  sim_cia pc;
  uint32_t sp;
};
```

- `regs[8]`：R0～R7；
- `pc`：实现内部使用的 byte 地址 PC；
- `sp`：实现栈所用的内部指针，不是 ISA 可见寄存器。

取得私有状态：

```c
struct example_sim_cpu *example_cpu = EXAMPLE_SIM_CPU (cpu);
```

宏最终读取 `CPU_ARCH_DATA(cpu)`。这块空间在 `sim_open` 中由 `sim_cpu_alloc_all_extra` 分配。

## 4. 代码边界

可以把整个实现分成四块：

```text
前端层       common/nrun.c
恢复/停止层  common/sim-resume.c + event engine
端口胶水层   example-synacor/interp.c
架构语义层   example-synacor/sim-main.c
```

公共层只知道“让 CPU 执行”，不知道 opcode 9 是 ADD；架构层只需调用 `sim_core_*`、`sim_io_*`、`TRACE_*` 和 `sim_engine_halt`，不必重新实现内存管理、终端抽象或单步机制。

## 5. 构建关系

`local.mk` 生成两个主要产物：

```text
example-synacor/libsim.a
example-synacor/run
```

`libsim.a` 包含公共 simulator 对象以及：

```text
interp.o
sim-main.o
sim-resume.o   <- 由 common/sim-resume.c 编译而来
```

`run` 则链接：

```text
nrun.o         <- 由 common/nrun.c 编译而来
libsim.a
SIM_COMMON_LIBS
```

所以 `example-synacor` 目录里看不到 `main()` 是正常的；独立程序的 `main()` 来自公共 `nrun.c`。

## 6. 推荐第一次阅读时暂时忽略的内容

第一次不要陷入这些细节：

- Automake 的 `%C%`、`%D%` 展开；
- module 自动生成机制；
- 多 CPU 调度参数；
- GDB remote protocol；
- BFD 的所有目标格式；
- trace/profile 的全部宏配置。

先抓住单 CPU 路径：

```text
nrun main -> sim_open -> sim_load -> sim_create_inferior
           -> sim_resume -> sim_engine_run -> step_once
```
